# Current UI and integration review

Status on 2026-10-01: the full guide is actively being expanded and the new
image-first UI has not received fresh integration acceptance. Prior critics gave
the bounded four-rock software a pass while explicitly withholding complete
field-guide acceptance.

The baseline demonstrated map/list/deep-link consistency, keyboard/back focus,
search aliases, grade ranges, uncertainty disclosures, nearby selection and
local offline navigation at 320px, 390px and desktop. The warm parchment,
editorial typography and restrained map treatment matched the existing MTN
identity. Known-climb lookup exposed concise beta; this does not justify making
text the default boulder-opening experience.

User review now requires tap boulder → see boulder immediately. Face controls must
be compact and integrated with the image. Finding directions stay collapsed;
redundant face-count prose is removed. A scrollable grade-sorted climb list must
coordinate with highlighted route geometry, to the side on wider layouts and
beneath or in an appropriate mobile sheet. Image framing preserves relevant
starts, finishes and recognition context.

Full coverage is essential: every known source unit and route must appear with
an explicit status, including unresolved records. The previous 58-record slice,
one Pearl context photo and synthetic topo calibration do not meet the final
product bar. No current software pass should hide missing lawful imagery,
physical identity, route geometry or map-footprint evidence.

Fresh separate critics must inspect the rendered expanded product for route
facts, physical face accuracy, map placement/shape, UI field use,
offline/resilience and whole-product integration. A builder's description is not
an acceptance artifact. Resolve current findings in the live
[Gauntlet findings](kraft-gauntlet-findings.md) and
[blocker list](kraft-open-blockers.md); keep one current conclusion per domain.
